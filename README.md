# Riff Sketchbook

기타 리프를 녹음하고 여러 테이크를 비교한 뒤, 앨범처럼 정리하는 개인용 로컬 웹앱입니다.

화면을 확장하거나 수정할 때는 [`DESIGN-GUIDE.md`](./DESIGN-GUIDE.md)의 컬러,
Pretendard 위계, 앨범·녹음 화면, 아이콘과 접근성 원칙을 기준으로 사용합니다.
완성 범위와 마지막 자동·통합 검증 결과는 [`QUALITY-REPORT.md`](./QUALITY-REPORT.md)에
정리되어 있습니다.

## 새 Mac에서 처음 설치

현재 Finder 실행기와 임시 공유 기능은 Apple Silicon Mac을 기준으로
합니다. 먼저 아래 항목을 준비하세요.

- Git
- Node.js 20.9 이상과 npm
- `/Applications/Postgres.app`에 설치된 [Postgres.app](https://postgresapp.com/)
- 처음 패키지·공유 도구를 받을 때 사용할 인터넷 연결

공개 저장소를 내려받은 뒤 실행합니다.

```bash
git clone https://github.com/joriih/guitar.git
cd guitar
npm ci
cp -n .env.example .env.local
```

Postgres.app의 관리자 이름이 macOS 로그인 계정과 다른 경우에만
`.env.local`의 `PG_ADMIN_USER`와 `PG_ADMIN_PASSWORD`, 또는 로컬 `PG_ADMIN_URL`을
설정합니다. 외부 PostgreSQL 주소는 앱이 거부합니다.

인터넷 임시 공유도 사용할 경우 아래 명령을 한 번 실행합니다.

```bash
npm run setup:share
```

이 명령은 Cloudflare의 [cloudflared 2026.8.2 공식 릴리스](https://github.com/cloudflare/cloudflared/releases/tag/2026.8.2)에서
Apple Silicon Mac용 압축 파일만 받습니다. GitHub 릴리스 자산과 압축을 풀어 나온
실행 파일의 SHA-256을 둘 다 고정값과 대조한 뒤 `.local-tools/cloudflared`에
설치합니다. 이 로컬 실행 파일은 Git에 올라가지 않습니다.

설치 상태를 확인하려면 서버를 열지 않고 아래 검사를 실행할 수
있습니다.

```bash
npm run typecheck
npm test
```

`.env.local`, `.local-tools`, `storage`의 녹음·복구·E2E 파일, `backups`는
저장소에 포함되지 않습니다. 따라서 새로 clone한 앱은 사용자 데이터가 없는
첫 설정 상태로 시작합니다. 실제 녹음과 백업을 Git에 강제로 추가하지 마세요.

## 실행하기

Finder에서 `Start Riff Sketchbook.command`를 더블클릭하면 PostgreSQL을 확인하고 앱을 엽니다.
앱이 바뀐 경우에만 실행용 파일을 자동으로 다시 준비하고, 평소에는 바로 열립니다.
앱이 열린 상태에서 파일이 바뀌었다면 기존 터미널에서 `Control + C`를 누른 뒤 다시
더블클릭해야 새 버전이 적용됩니다.

처음 한 번은 사용자 이름과 비밀번호를 직접 정하는 설정 화면이 표시됩니다. 이후에는 같은 비밀번호로 로그인합니다.

`이 Mac에서 로그인 유지`를 끄면 브라우저를 닫을 때 로그인이 풀립니다. 앱 안에서는 왼쪽 아래의 로그아웃 아이콘을 사용할 수 있습니다.

왼쪽 아래의 설정에서는 표시 이름과 사용자 이름, 비밀번호를 바꿀 수 있습니다. 비밀번호를 바꾸면 다른 브라우저의 로그인은 모두 종료되고 지금 사용하는 브라우저만 다시 연결됩니다. 같은 화면에서 앨범·리프·테이크·트랙 수, 연결된 오디오 용량, 삭제 후 오디오 정리 대기 건수와 최근 백업 시각도 확인할 수 있습니다.

## 한 사람에게 임시 공유

먼저 이 Mac의 `http://127.0.0.1:3000`에서 첫 설정을 끝내고 기존 앱 터미널을 종료한 뒤,
Finder에서 `Share Riff Sketchbook.command`를 더블클릭합니다. 공유 실행기는 Cloudflare
Quick Tunnel의 일회용 HTTPS 주소를 표시하며, 상대방은 별도 프로그램이나 계정 없이
일반 브라우저로 접속할 수 있습니다. 상대방도 Riff Sketchbook의 같은 사용자 이름과
비밀번호로 로그인합니다.

공유 주소로 로그인하면 앨범 보기뿐 아니라 녹음·수정·파일 추가·설정 변경까지 모두
가능합니다. 주소를 아는 누구나 로그인 화면에는 도달할 수 있으므로 주소와 비밀번호를
공개 채널에 함께 올리지 마세요. 공유 터미널을 `Control + C`로 끝내면 앱과 터널이 함께
종료되고 그 임시 주소도 닫힙니다. 다음 공유 때는 새 주소가 발급됩니다. 일반 로컬 실행과
임시 공유를 동시에 따로 켜지는 마세요. 실행기가 기존 프로세스를 발견하면 안전하게 중단합니다.

Quick Tunnel은 계정 없이 만드는 임시 공개 링크이며 운영 서비스 수준의 안정성을 보장하지
않습니다. 동시 연결은 최대 200개이고 SSE는 지원하지 않습니다. Mac의 잠자기, 네트워크 끊김,
공유 실행기 종료 때 링크가 사라집니다. 링크와 앱 로그인 정보를 모두 가진 사람은 전체 기능을
사용할 수 있으며, 터널 사용에는 Cloudflare의 서비스 약관이 적용됩니다.

공유 모드에서도 앱 서버와 PostgreSQL은 계속 `127.0.0.1`에만 연결됩니다. 앱은
`RIFF_REMOTE_ACCESS=1`과 경로 없는 정확한 HTTPS `APP_ORIGIN`이 함께 주어진 경우에만
그 주소의 변경 요청을 허용합니다. 누락되거나 비슷하게 생긴 다른 주소의 요청은 거부합니다.
로컬 주소와 공유 주소는 동시에 사용할 수 있지만 서로 다른 사이트이므로 각각 한 번씩
로그인해야 합니다. 자세한 Quick Tunnel 특성은
[Cloudflare 공식 문서](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)를 참고하세요.

## 저장 위치

- 앨범, 리프, 테이크 정보: 로컬 PostgreSQL의 `riff_sketchbook` 데이터베이스
- 실제 녹음 파일: 이 폴더의 `storage/audio`

영구 저장 위치는 이 Mac뿐이며 앱과 데이터베이스는 `127.0.0.1`에서만 열립니다.
기본 로컬 모드에서는 외부 서비스를 거치지 않습니다. 임시 공유 중에는 상대방과 주고받는
화면·오디오 트래픽이 암호화된 Cloudflare Tunnel을 통과하지만, 데이터베이스와 오디오
원본의 앱 저장 위치가 외부로 바뀌지는 않습니다.

테이크나 트랙을 삭제하면 데이터베이스 삭제와 오디오 정리 예약을 먼저 함께 저장합니다.
파일을 즉시 지우지 못하거나 그 사이 앱이 종료되어도 삭제된 항목이 다시 나타나지는 않으며,
남은 파일은 다음 앱 시작 때 안전한 경로인지 다시 확인한 뒤 자동 정리합니다.

## 백업

Finder에서 `Backup Riff Sketchbook.command`를 더블클릭하면 `backups` 폴더에
PostgreSQL 데이터와 연결된 오디오 파일을 함께 보관합니다. 백업마다 파일 크기와
SHA-256 무결성 정보가 들어 있는 `manifest.json`도 생성됩니다. 중요한 녹음을 남긴
날에는 이 백업 폴더를 외장 디스크나 별도 저장소에 한 번 더 복사해두는 것을 권장합니다.
앱이 열린 상태에서도 백업할 수 있습니다. 데이터베이스 스냅샷과 오디오 복사가 끝날
때까지 테이크·트랙 추가나 삭제 요청은 잠시 기다릴 수 있지만, 삭제와 파일 복사가
엇갈린 불완전한 백업은 만들지 않습니다.

복원할 때는 실행 중인 앱을 먼저 종료하고 `Restore Riff Sketchbook.command`를 더블클릭한
뒤 백업 폴더를 선택하면 됩니다. 선택한 백업의 모든 체크섬을 먼저 검사하고, 현재 상태도
새 백업으로 남긴 뒤 데이터베이스와 오디오를 함께 복원합니다. 복원이 끝나면 보안을 위해
기존 로그인 세션은 이어지지 않습니다. 사용자 이름과 비밀번호도 백업 당시 상태로 돌아가므로
반드시 **그 백업을 만들 당시의 사용자 이름과 비밀번호**로 다시 로그인해야 합니다. 현재
비밀번호로 자동 변경하거나 초기화하지는 않습니다.

백업에 연결되지 않았던 기존 오디오 파일은 복원 성공 뒤에도 지우지 않고
`storage/recovery/orphan-audio-…` 폴더에 따로 보존합니다. 앱에는 자동으로 나타나지 않으므로
해당 폴더의 `복구 안내-….txt`와 파일을 Finder에서 확인해주세요.

복원 도중 Mac이 꺼지거나 프로세스가 강제 종료되면 `storage`에 복원 저널과
`.restore-…` 폴더가 남을 수 있습니다. 이때 앱 시작·백업·다른 복원은 데이터와 오디오가
엇갈리지 않도록 자동으로 중단됩니다. 해당 파일을 임의로 삭제하거나 이름을 바꾸지 말고,
`backups`의 가장 최근 자동 안전 백업과 `storage/recovery`를 함께 보존한 상태에서 복구해야
합니다. 복원 터미널에 표시된 파일 이름과 저널의 `phase`를 확인하면 중단 지점을 알 수 있습니다.

데이터베이스와 실제 오디오 파일이 잘 연결되어 있는지 확인하려면 앱 폴더의 터미널에서
`npm run doctor`를 실행할 수 있습니다. 누락된 파일이나 크기 불일치가 있으면 백업 전에
알려주며, 자동 정리가 예약된 파일은 경로를 노출하지 않고 대기 건수로 표시합니다. 그 밖의
사용하지 않는 파일은 자동으로 지우지 않고 주의 항목으로만 표시합니다. 정확히 한 시점의
데이터와 파일을 비교하기 위해 앱을 먼저 종료한 뒤 실행해야 하며, 백업·복원 중이거나
끝나지 않은 복원 흔적이 있으면 섞인 상태를 정상으로 오인하지 않도록 점검을 중단합니다.

## 녹음 팁

- 처음 `입력 연결`을 누르면 브라우저의 마이크 권한을 허용해주세요.
- 오디오 인터페이스가 연결되어 있으면 입력 목록에서 선택할 수 있습니다.
- `R`은 녹음 시작/정지, `Space`는 선택한 테이크 재생/일시정지입니다.
- BPM 옆의 `TAP`을 박자에 맞춰 누르면 템포를 자동으로 계산해 저장합니다.
- 카운트인과 반복 녹음을 켜면 반복 구간마다 새 테이크가 만들어집니다.
- 테이크 설정에서 대표 테이크, 이름, 앞뒤 트림, 시작 위치와 분할을 조정할 수 있습니다.
- 제목, BPM, Key, 박자, 튜닝, TAB과 메모는 입력 후 자동 저장됩니다.
- 타임라인의 현재 재생 위치에 구간 마커를 추가하고 이름·시간·색상을 정할 수 있습니다. 마커를 누르면 해당 위치로 바로 이동합니다.
- 저장에 실패했거나 화면 이동 중 끝난 녹음은 복구 목록에 남아 개별 재생, 재저장, 다운로드가 가능합니다.
- 종료할 때는 실행 중인 터미널 창에서 `Control + C`를 누르면 됩니다.

## 연습 도구

로그인 뒤 왼쪽의 `연습 도구`에서 스케일·코드 구성음을 프렛보드로 확인하고,
5프렛 단위 구간과 카포 위치별 장·단조 오픈 코드 폼을 비교할 수 있습니다. 계산 로직은
[`lib/music-theory.ts`](./lib/music-theory.ts)의 순수 TypeScript 함수로 분리되어 있어 다른
화면이나 프로젝트에서도 가져다 쓸 수 있습니다.

이 기능의 출발점이 된 기존 `joriih/guitar` 정적 앱 원본은
[`legacy/guitar-trainer`](./legacy/guitar-trainer)에 비배포 보관했습니다. 현재 화면에 옮기지
않은 리듬·메트로놈·합성 백킹·귀 훈련·타이머 코드도 그 안에 남아 있으므로, 원격 원본
저장소를 정리하더라도 기능 소스가 사라지지 않습니다.

## 앨범 정리

- `모든 앨범`의 `새 앨범`에서 이름, 메모, 색상과 Fender 기타 커버를 정해 Drive 폴더처럼 만들 수 있습니다.
- 앨범 안의 `앨범 수정`에서 이름, 메모, 색상과 기타 커버를 바꿀 수 있습니다.
- 앨범 안에서 새 리프를 만들면 해당 앨범이 자동 선택됩니다.
- 리프의 더보기 메뉴에서 다른 앨범이나 `분류되지 않음`으로 옮길 수 있습니다.
- 리프의 더보기 메뉴에서 전체 테이크·트랙·Comp·마커·태그를 포함한 안전한 복사본을 만들 수 있습니다.
- 편집 화면에서 리프마다 태그를 붙일 수 있고, 홈 검색과 태그 필터로 관련 스케치를 모아볼 수 있습니다.
- 리프 목록의 별 버튼으로 즐겨찾기를 모을 수 있습니다.
- 필요 없는 리프는 휴지통으로 옮긴 뒤 원래 앨범으로 복원할 수 있습니다. 휴지통 이동은
  녹음 파일을 지우지 않는 안전한 방식이며, 영구 삭제는 제공하지 않습니다.

## 트랙 · Comp · 펀치

- MP3, WAV, AIFF, M4A/AAC, FLAC, OGG/Opus, WebM 파일을 반주나 기타 트랙으로 여러 개 추가할 수 있습니다. 파일당 최대 크기는 95MB입니다.
- 가져온 트랙별 `M`(음소거)·`S`(솔로), 볼륨, 팬, 시작 위치, 페이드를 조정할 수 있습니다.
- 여러 테이크에서 좋은 구간만 골라 Comp로 저장하고 함께 미리 들을 수 있습니다.
- 펀치 녹음은 먼저 상단의 `입력 연결`을 누른 뒤 IN/OUT과 프리롤을 정해 실행해주세요.
- 현재 믹스는 24-bit WAV로 내보낼 수 있으며, 연결한 입력으로 기타 튜너도 사용할 수 있습니다.

미리 듣기, 일반 녹음 위 반주, 펀치 녹음과 WAV 내보내기는 모두 같은 음소거·솔로·볼륨·팬·페이드 설정을 사용합니다. 조정 내용은 연결이 잠시 끊겨도 로컬 복구함에 남았다가 다시 저장됩니다.

## 자체 점검

앱을 업데이트하거나 중요한 녹음을 마친 뒤에는 아래 검사를 사용할 수 있습니다.

- `npm test`: 녹음 시간 계산, 오디오 믹스, 태그·커버·인증 같은 핵심 동작 검사
- `npm run test:ops`: 로컬 DB 제한, 시작·백업·복원 잠금과 강제 종료 복원 저널 검사
- `npm run test:e2e`: 임시 데이터베이스와 별도 오디오 폴더에서 가입부터 녹음·복구까지 실제 API 흐름 검사
- `npm run doctor`: 현재 데이터베이스와 오디오 파일의 연결 상태 검사

`test:e2e`는 실제 라이브러리와 분리된 임시 공간만 사용하고 끝나면 해당 데이터베이스와 파일을 정리합니다. 실제 마이크·오디오 인터페이스의 음질과 지연 시간은 연결한 장비와 브라우저 권한에 따라 달라질 수 있으므로 첫 녹음 전에 짧게 입력 테스트를 해주세요.
